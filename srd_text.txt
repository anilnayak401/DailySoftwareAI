1. Executive Summary
DailySoftwareAI.com is a branded software discovery, ranking, review, and launch-tracking website. It curates AI tools, SaaS products, automation and marketing software, and lifetime deals, then earns affiliate revenue when visitors click through and purchase. The experience must feel like a modern, trustworthy, premium software directory — never a cheap affiliate blog.
The one-week reality check
This document is written for a beginner developer with a hard one-week deadline. Wherever the ideal architecture conflicts with shipping on time, this spec explicitly chooses the simpler path and documents the upgrade path for later.
MVP target: a polished homepage, dynamic product & category pages loading from a real database, working affiliate redirects with click logging, core SEO, a protected admin panel, and a production deployment on Vercel.

What we are building (MVP)
A premium homepage that reuses the existing 3D hero and presents a #1 pick, trending products, launches, and category showcases.
Dynamic, SEO-friendly product pages at /products/[slug] generated from the database.
Category pages at /categories/[slug] with filtering and breadcrumbs.
A launch calendar at /launches with timezone-aware launch dates.
A safe affiliate redirect system at /go/[slug] that logs clicks and prevents open redirects.
A simple, secure admin dashboard at /admin to add and manage products.
SEO essentials: metadata, sitemap, robots.txt, structured data, and the required legal/trust pages.
Recommended stack at a glance
Next.js (App Router) + TypeScript + Tailwind CSS on the frontend; Supabase (PostgreSQL + Auth + Storage) as the backend; deployed on Vercel. Analytics via Google Analytics 4 and Search Console. Automation with n8n is explicitly deferred to a later phase.

4. User Journeys
Journey A — Discovery to affiliate click (primary revenue path)
User lands on the homepage from search/social and sees the 3D hero + #1 pick.
They scan Trending and Best-of category cards, and tap a product card.
The product page loads with rating, editor score, pros/cons, pricing, and FAQ.
User taps 'Visit Deal', which hits /go/[slug].
The redirect route logs the click and forwards to the stored affiliate URL.
Journey B — Launch tracker
User visits /launches or the 'Launching Today' homepage section.
They see timezone-adjusted launch times and optional countdowns.
They tap 'View Review' to read the page, then 'Visit Deal' to buy on launch.
Journey C — Category browsing + filtering
User opens /categories/ai-tools from the nav or a category card.
They filter by pricing type and sort by highest rated.
They open a product and convert via the affiliate CTA.
Journey D — Admin publishing
Naresh logs into /admin securely.
Adds a product: name, logo, description, category, affiliate URL, launch date, rating, rank.
Marks it featured/trending/top-pick and publishes.
The public product page and redirect become live automatically.

The homepage is a curated storefront, not a wall of links. Each section is a reusable server component pulling published products from Supabase. Sections render top-to-bottom in the order below.
Section 1 — Header / Navigation
Purpose: Persistent, accessible navigation and search.
User Story: As a visitor, I can reach any major area of the site from any page.
Priority:  P0    Scope: MVP
Contents: DailySoftwareAI logo, Home, Products, Categories, Launch Calendar, Top Rated, About, Search, and an optional 'Submit a Product' CTA.
Desktop: horizontal nav, sticky on scroll with a subtle shadow after ~40px.
Mobile: hamburger opens a MobileMenu drawer; search collapses into an icon that expands a field.
Active state: current section highlighted via aria-current and an accent underline.
Accessibility: nav is a <nav> landmark, links are keyboard-focusable with visible focus rings, drawer traps focus and closes on Esc.
Section 2 — Hero (keep existing 3D hero)
Purpose: Immediate positioning and two clear CTAs.
Priority:  P0    Scope: MVP
Suggested copy
Headline: “Discover the Best Software & AI Tools — Before Everyone Else”
Sub: Daily rankings, new launches, expert picks, and software deals for creators, marketers, founders, and businesses.
Primary CTA: Explore Top Products → scrolls to / links to Trending. Secondary CTA: View New Launches → /launches.
Do not rebuild the 3D hero. Lazy-load/defer the 3D canvas so it never blocks Largest Contentful Paint; render a lightweight static fallback for reduced-motion users and low-power devices.

12. Affiliate Link Requirements
Purpose: A safe, trackable redirect layer so raw affiliate URLs are never exposed and every click is logged.
User Story: As the site owner I want every 'Visit Deal' click routed through my domain, logged, and safely forwarded.
Priority:  P0    Scope: MVP
Redirect structure
Pattern: dailysoftwareai.com/go/[product-slug]  —  e.g. /go/example-product.
Flow
User clicks 'Visit Deal'.
Request reaches the /go/[slug] route (Next.js route handler / server).
System looks up the product by slug and finds its active affiliate URL.
System records a permitted click event (timestamp, product id, referrer/UTM where appropriate).
System issues a 302 redirect to the stored affiliate URL.
Implementation (Next.js + Supabase)
Create app/go/[slug]/route.ts as a server route handler. It runs on the server, so the affiliate URL never ships to the browser HTML.
Query Supabase for the product + its affiliate_links row (status = active). Insert a row into click_events. Then return Response.redirect(url, 302).
Storage: keep affiliate URLs in an affiliate_links table keyed by product_id and network, with a status column so offers can be disabled.
Required behaviors & safeguards
Concern
Requirement
Click logging
Log timestamp, product_id, network; store referrer & UTM only where legally/technically appropriate
UTM handling
Preserve/append UTM params if the network allows; never strip required tracking params
Bot filtering
Optionally skip logging for known bots (user-agent + no-JS heuristics) — Phase 2
Broken link handling
If URL missing/invalid, show a friendly 'offer unavailable' page, not a crash
Disabled offers
If status != active, do not redirect; show 'this deal has ended' with alternatives
Open-redirect prevention
Only redirect to URLs stored in the DB; never redirect to a URL taken from user input/query
URL validation
Validate stored URLs are absolute https and on an allow-list of known networks
Security
rel="sponsored nofollow noopener", target="_blank" on outbound links
Compliance
The implementation must respect each affiliate network's terms of service and required disclosures (JVZoo, WarriorPlus, direct programs, etc.). Show an affiliate disclosure near every affiliate CTA and on a dedicated /affiliate-disclosure page.

18. Performance Requirements
Core Web Vitals targets: LCP < 2.5s, CLS < 0.1, INP < 200ms on mobile.
Images via next/image with width/height set to prevent layout shift; lazy-load below-the-fold images and screenshots.
The 3D hero must be deferred/lazy-loaded and must not block LCP; provide a static fallback for reduced-motion and low-power devices.
Caching: use SSG/ISR for product & category pages; cache Supabase reads where possible.
Database: index slug, status, rank, launch_date; select only needed columns; paginate lists.
Fonts: use next/font with font-display: swap; preload the primary font; limit weights.
Mobile: minimize JS on the homepage; keep the 3D canvas off the critical path.
